# ТЗ: создание заметки (Android)

> Цель: дать понятный способ создать новую страницу-заметку в **выбранном разделе** дерева.  
> Паритет с Windows: папка на диске + `index.html` (модель «каждая папка = страница»).  
> Вне скоупа v1: rename / delete — delete: см. `docs/notes-delete-android-spec.md`.

## 1. Контекст

Сейчас Android Notes: выбрать SAF-корень → листать дерево → открыть/редактировать.  
**Создать / переименовать / удалить** — нет. На Windows: context «New Page» и toolbar «New folder» создают подпапку + `index.html` и открывают её.

## 2. Принципы UX

1. **Раздел = родитель.** Новая заметка всегда появляется *внутри* выбранного пользователем раздела (папки в дереве), не «где попало» и не только в корне.
2. **Один главный жест.** На экране списка заметок всегда видна одна явная кнопка «Новая заметка» (FAB или кнопка в app bar) — не спрятана только в long-press.
3. **Понятный родитель.** Перед/в момент создания пользователь видит, *куда* попадёт заметка (название раздела).
4. **Сразу в редактор.** После создания открывается новая пустая (с заголовком) страница — как на Windows.
5. **Без сюрпризов в редакторе.** Если открыт редактор заметки, «создать» либо возвращает к дереву с подсказкой, либо создаёт *соседа/ребёнка* с явным выбором — см. §4.

## 3. Модель данных (как Windows)

| Понятие UI | На диске |
|------------|----------|
| Раздел / страница | Каталог |
| Содержимое | `index.html` (создать при New) |
| Вложенность | Подкаталоги |

Шаблон новой страницы (как Win):

```html
<h1>{Имя}</h1>
<p><br></p>
```

Имя папки = введённое имя (после sanitize). Относительный путь: `{parentRelative}/{name}`.

## 4. Куда создаём (правила родителя)

Обозначения:
- **Выбранный узел** — строка дерева, которая сейчас selected / last-focused в списке.
- **Корень** — SAF notes root (нельзя «создать вместо корня»; корень только parent для верхнего уровня).

| Состояние UI | Родитель новой заметки | Пояснение пользователю |
|--------------|------------------------|-------------------------|
| Открыт список, выбран узел A | **A** (внутри A) | «В разделе: {имя A}» |
| Открыт список, ничего не выбрано | **Корень** | «В корне заметок» |
| Открыт редактор страницы B | По умолчанию **родитель B** (сосед B) *или* явный выбор — см. ниже | Не создавать «вслепую» внутри B без подтверждения |

**Рекомендуемое поведение (v1, компактный телефон):**

1. Основной CTA «＋» живёт на **экране дерева** (список разделов/заметок).
2. В **редакторе** в overflow / app bar: пункт «Новая заметка…» →  
   - диалог: куда создать — «В этом же разделе» (= parent текущего) / «Внутри этой заметки» (= текущая как parent);  
   - default: **«В этом же разделе»** (сосед) — привычнее OneNote «страница рядом».
3. Wide layout (дерево + редактор рядом): CTA на панели дерева; родитель = selected в дереве (если нет selection → корень).

Альтернатива проще (если режем scope): CTA только на дереве; из редактора сначала Back, потом ＋. Хуже по скорости, зато нулевая двусмысленность. **Предпочтение ТЗ: вариант с диалогом «куда» из редактора (§ выше).**

## 5. UI: список (дерево)

### 5.1. Кнопка

- **FAB** справа внизу над списком: иконка `＋` / «New note».  
  На широком экране допустима текстовая кнопка в top bar дерева рядом с Refresh.
- Disabled, если нет notes root (показан empty state «Choose notes folder»).

### 5.2. Диалог создания

Заголовок: **«Новая заметка»**.

Поля:
1. Текст: **«Раздел: {имя родителя}»** (если корень — «Корень заметок»). Смена раздела в v1 — через выбор другой строки в дереве *до* нажатия ＋ (не нужен отдельный picker).
2. Поле ввода **«Название»** (обязательное), placeholder например «Без названия» не подставлять автоматически в имя папки — требовать непустой trim.
3. Кнопки: **Отмена** / **Создать**.

Клавиатура: IME сразу в поле названия; Enter = Создать.

### 5.3. После успеха

1. Создать каталог + `index.html` через SAF.
2. Развернуть предков в дереве, обновить список.
3. Выбрать новую строку и открыть редактор (как `selectNotesNode`).
4. Snackbar краткий: «Создано в «{родитель}»» (optional).

### 5.4. Long-press (дополнение, не вместо FAB)

Long-press на узле → меню: **«Новая заметка здесь»** (= parent = этот узел).  
Тот же диалог имени. Нужен для discoverability «создать внутри».

## 6. Валидация и ошибки

| Случай | Поведение |
|--------|-----------|
| Пустое имя | Не создавать; ошибка под полем |
| Недопустимые символы `\ / : * ? " < > \|` и ведущие/хвостовые `.` | Sanitize или отказ с текстом |
| Имя уже есть у sibling | «Уже есть заметка с таким именем» |
| Нет прав SAF / IO fail | Диалог ошибки, дерево не ломать |
| Имя слишком длинное (лимит FS/SAF) | Обрезать с предупреждением или отказать |

Регистр имён: на Android/SAF обычно case-sensitive зависит от провайдера — сравнивать sibling **case-insensitive** для UX (как Win OrdinalIgnoreCase).

## 7. Синхронизация

- Новая папка + `index.html` — обычные файлы в notes root → подхватятся **local-only push** / full reconcile Cloud (как любое изменение FS).
- Notes UI **не** вызывает cloud API напрямую.
- После create: не блокировать UI ожиданием sync; достаточно локального появления в дереве.

## 8. Локализация / копирайт (EN v1, как остальной UI)

- FAB contentDescription: `New note`
- Dialog title: `New note`
- Label: `Section: {name}` / `Notes root`
- Field: `Title`
- Actions: `Cancel` / `Create`
- Editor menu: `New note…`
- Destination radios: `Same section` / `Inside this note`

(RU строки — по желанию во 2-й итерации, сейчас UI в основном EN.)

## 9. Технический набросок (не UI)

- `MainViewModel.createNote(parentRelativePath: String, name: String): Result`
- SAF: create directory under parent document id + write `index.html` (переиспользовать примитивы из `Adapters` / `NotesTreeBuilder.ensureIndexHtml`, не дублировать Cloud «New folder»).
- После create: `refreshNotesTree()` + `selectNotesNode(newRow)`.
- Не создавать заметку без root.
